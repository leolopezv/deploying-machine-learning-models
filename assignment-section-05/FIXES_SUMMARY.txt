ISSUE 1: NumPy Compilation Failure
----------------------------------
PROBLEM:
  - NumPy 1.26.4 attempted to build from source
  - System lacked required C compiler
  - Error: "Unknown compiler(s): [['icl'], ['cl'], ['cc'], ['gcc'], ...]"
  - Error: "Failed to activate VS environment: vswhere.exe not found"

ROOT CAUSE:
  - Old version pinning with upper bounds (<2.0.0) prevented installation
    of modern pre-built wheel distributions
  - Newer NumPy versions (1.26+) are only available as pre-built wheels
    for Python 3.13

SOLUTION:
  - Updated requirements.txt to remove upper version bounds
  - Allows pip to use pre-built wheel distributions instead of building
    from source
  - Updated all dependency version constraints

FILE MODIFIED:
  - requirements/requirements.txt

COMMANDS EXECUTED:
  $ pip install --only-binary :all: numpy
  $ pip install --upgrade -r requirements/requirements.txt


ISSUE 2: Pydantic v2 Field Name Conflict
-----------------------------------------
PROBLEM:
  - Field name "model_config" is reserved in Pydantic v2
  - Error: "model_config cannot be used as a model field name"
  - Error: "'dict' object has no attribute 'model_config'"

ROOT CAUSE:
  - Pydantic v2 introduced breaking changes
  - "model_config" is now used for model configuration (reserved keyword)
  - Old code used this as a regular field name

SOLUTION:
  - Renamed field "model_config" to "model_config_" throughout codebase
  - Updated all references to use the new field name
  - Applied changes consistently across 8 files

ISSUE 3: Type Annotation Violation
-----------------------------------
PROBLEM:
  - Function parameter with None default but non-Optional type annotation
  - MyPy error: "Incompatible default for argument 'cfg_path'"
  - Error: "default has type 'None', argument has type 'Path'"

ROOT CAUSE:
  - fetch_config_from_yaml() declared parameter as "Path" but default is None
  - PEP 484 requires explicit Optional type for nullable parameters

SOLUTION:
  - Updated function signature to use Python 3.10+ union syntax
  - Changed "cfg_path: Path = None" to "cfg_path: Path | None = None"
  - Modern syntax is cleaner and more readable

FILE MODIFIED:
  - classification_model/config/core.py

CHANGE:
  - Line 57: fetch_config_from_yaml(cfg_path: Path = None) -> YAML
  - Changed to: fetch_config_from_yaml(cfg_path: Path | None = None) -> YAML


ISSUE 4: Pydantic ValidationError API Change
---------------------------------------------
PROBLEM:
  - ValidationError handling code failed with Pydantic v2
  - Error.json() method changed or became incompatible
  - Validation schema had unnecessary/incorrect fields

ROOT CAUSE:
  - ValidationError API changed between Pydantic v1 and v2
  - Schema included fields that are dropped during preprocessing
  - Type definitions didn't match actual data types

SOLUTION:
  - Kept error.json() which still works in Pydantic v2
  - Updated TitanicDataInputSchema to match actual features
  - Fixed type annotations and made all fields Optional with defaults
  - Removed unused fields: name, ticket, boat, body, home.dest

FILE MODIFIED:
  - classification_model/processing/validation.py

CHANGES:
  1. Line 1: Removed "Union" from imports (no longer needed)
  2. Lines 29-39: Updated TitanicDataInputSchema
     - Removed: name, ticket, boat, body (not in features list)
     - Updated: age type from Optional[int] to Optional[float]
     - Added: title field (generated from name during preprocessing)
     - Added: default None values to all Optional fields for clarity

SCHEMA BEFORE:
  class TitanicDataInputSchema(BaseModel):
      pclass: Optional[int]
      name: Optional[str]
      sex: Optional[str]
      age: Optional[int]
      sibsp: Optional[int]
      parch: Optional[int]
      ticket: Optional[int]
      fare: Optional[float]
      cabin: Optional[str]
      embarked: Optional[str]
      boat: Optional[Union[str, int]]
      body: Optional[int]

SCHEMA AFTER:

================================================================================
LESSONS LEARNED
================================================================================

1. VERSION PINNING STRATEGY
   - Upper bounds can become problematic as the ecosystem evolves
   - Consider using loose upper bounds or removing them when appropriate
   - Pre-built wheels are preferred over source builds when available

2. PYDANTIC V2 MIGRATION
   - Field name "model_config" is reserved in v2
   - ValidationError API changed between versions
   - Type annotations become stricter (no implicit Optional)

3. TYPE CHECKING
   - MyPy catches issues that runtime testing might miss
   - PEP 484 conventions are important for code quality
   - Optional types should be explicitly declared

4. TESTING WORKFLOW
   - Use tox for reproducible test environments
   - Run all environments (tests, checks, train) before deployment
   - Code formatting (black, isort) keeps code consistent
